# Fixtures

Small sample inputs shared by tests across the repository. Every file stays under 200 KB. The package `@easyimmerse/fixtures` exposes `fixturePath`, `readFixtureText`, and `readFixtureBytes` from `index.ts` so TypeScript tests can locate and read these files without hard-coded paths.

## sample.srt

Four SubRip cues between 0 and 5 seconds, written with CRLF line endings on purpose. Cue 2 spans two lines of text and cue 3 contains `<i>` inline markup. The text pairs with the dictionary fixture, so it mentions a cat, a dog, eating, and quiet.

Hand-written. To regenerate, edit the file with an editor that preserves CRLF, or run:

```sh
printf '1\r\n00:00:00,500 --> 00:00:01,500\r\nThe cat is sleeping.\r\n\r\n2\r\n00:00:01,750 --> 00:00:03,000\r\nThe dog wants to eat.\r\nIt is hungry.\r\n\r\n3\r\n00:00:03,250 --> 00:00:04,000\r\n<i>Everything</i> is quiet.\r\n\r\n4\r\n00:00:04,250 --> 00:00:05,000\r\nGood night.\r\n' > fixtures/sample.srt
```

## sample.vtt

The same four cues as `sample.srt` in WebVTT form, with LF line endings: a `WEBVTT` header, a `NOTE` block, a cue identifier on every cue, and `line:90% align:center` settings on cue 3. Keep it in sync with `sample.srt` and with the subtitle track inside the video fixture.

Hand-written. Edit directly.

## sample-epub/ and sample.epub

An unzipped EPUB 3 source tree and its packaged form. The book is titled "Sample Book", is in English, and has two chapters plus a navigation document. Chapter two contains an inline `<span>` so text extraction has to merge inline elements.

To regenerate `sample.epub` after editing the tree (the `mimetype` entry must come first and be stored uncompressed):

```sh
cd fixtures/sample-epub && rm -f ../sample.epub && zip -X0 ../sample.epub mimetype && zip -Xr9D ../sample.epub META-INF OEBPS
```

## sample-yomitan/ and sample-yomitan.zip

A Yomitan dictionary in format version 3 with three term entries: 猫 (cat), 犬 (dog), and 食べる (to eat). `index.json` holds the dictionary metadata and `term_bank_1.json` holds the entries.

To regenerate `sample-yomitan.zip` after editing the tree:

```sh
cd fixtures/sample-yomitan && rm -f ../sample-yomitan.zip && zip -X9 ../sample-yomitan.zip index.json term_bank_1.json
```

## sample-yomitan-en/ and sample-yomitan-en.zip

An English-German Yomitan dictionary in format version 3, titled "Sample English-German". `index.json` declares `sourceLanguage` "en" and `targetLanguage` "de". `term_bank_1.json` holds nine entries with empty readings, each for a word that appears in `sample.srt`: cat (Katze), dog (Hund), sleep (schlafen), eat (essen), hungry (hungrig), quiet (ruhig), night (Nacht), everything (alles), and good (gut).

To regenerate `sample-yomitan-en.zip` after editing the tree:

```sh
cd fixtures/sample-yomitan-en && rm -f ../sample-yomitan-en.zip && zip -X9 ../sample-yomitan-en.zip index.json term_bank_1.json
```

## sample-yomitan-structured/ and sample-yomitan-structured.zip

A Japanese-English Yomitan dictionary in format version 3 that exercises every kind of glossary item. `term_bank_1.json` holds three entries: 猫 (cat) with one structured-content item that contains a span, a list, and an `img` node; 犬 (dog) with a text item, an image item, and a plain string; and 食べた with a deinflection item pointing to 食べる. The archive also holds `tag_bank_1.json`, a `styles.css` stylesheet, and the image `img/cat.svg` that both image references point to.

To regenerate `sample-yomitan-structured.zip` after editing the tree:

```sh
cd fixtures/sample-yomitan-structured && rm -f ../sample-yomitan-structured.zip && zip -X9 ../sample-yomitan-structured.zip index.json term_bank_1.json tag_bank_1.json styles.css img/cat.svg
```

## Media fixtures

Generated by `generate-media.sh` (`mise run fixtures:media`). Never edit them by hand; change the script and regenerate.

- `sample.mp4`: five seconds of the ffmpeg test pattern (320x180, H.264) with a 440 Hz sine tone (mono AAC) and `sample.srt` embedded as a `mov_text` subtitle track tagged `eng`.
- `sample.mkv`: the same content with the subtitle track stored as SubRip text, for Matroska metadata tests.
- `sample.mp3`: three seconds of a 440 Hz sine tone, mono, 64 kbps.
- `conversion.mkv`: 24 seconds of synthetic video and audio for conversion and seek-accuracy tests, described below.
- `conversion.mp3`: the first 10 seconds of the `conversion.mkv` audio as a raw VBR MP3 (LAME `-q:a 7`, 48 kHz stereo), for the case where a browser seeks inaccurately in raw MP3.

### conversion.mkv

Video is H.264 at 128x72, exactly 24000/1001 fps (about 23.976), with up to three consecutive B-frames. It holds 576 frames; frame `n` has the presentation time `n * 1001 / 24000` seconds, stored rounded to the millisecond (Matroska's time base is 1 ms). The container duration is 24.024 s, and both streams start at 0.

Each frame shows its own index. The top half (rows 0 to 35) is divided into 16 columns, each 8 pixels wide. Column `i`, counted from the left, carries bit `i` of the frame index: white (255) means 1 and black (0) means 0. The bottom half is gray (128), though compression shifts it by up to 31 next to the boundary row. To decode a frame, read the luma at the center of each column (for example row 18, x = `8 * i + 4`) and treat values above 128 as 1. Decoded values stay within 4 of 0 or 255.

Keyframes vary in spacing so that segments cut at keyframes have different lengths. Eight keyframes are forced at irregular times and the encoder adds one whenever 96 frames pass without one:

| Keyframe time (s) | Frame index | Frames until the next keyframe |
| ----------------- | ----------- | ------------------------------ |
| 0.000             | 0           | 36                             |
| 1.502             | 36          | 29                             |
| 2.711             | 65          | 82                             |
| 6.131             | 147         | 26                             |
| 7.216             | 173         | 96                             |
| 11.220            | 269         | 41                             |
| 12.930            | 310         | 26                             |
| 14.014            | 336         | 96                             |
| 18.018            | 432         | 31                             |
| 19.311            | 463         | 96                             |
| 23.315            | 559         | 17 (end of file)               |

Audio is MP3 (libmp3lame, 32 kbps CBR, 48 kHz, stereo with identical channels). It is the sum of two signals:

- A sine tone at amplitude 0.3 whose frequency is `300 + 50 * k` Hz during second `k` (300 Hz from 0 to 1 s, 350 Hz from 1 to 2 s, and so on). Each step falls on a whole second and each frequency is a whole number of hertz, so the phase is continuous at the steps.
- A click once per second: a 5 ms burst of a 2 kHz sine at amplitude 0.6 that starts at `k + 0.1 * (k mod 5)` seconds (0.0, 1.1, 2.2, 3.3, 4.4, 5.0, 6.1, and so on).

The decoded audio is aligned with these nominal times to within 0.1 ms; ffmpeg removes the encoder delay. MP3 pre-echo can put audible energy up to about 10 ms before a click, so locate clicks by cross-correlating against the burst rather than with an amplitude threshold.

`conversion.mp3` carries the same signal for 10 seconds. ffprobe reports its stream start time as 0.023 s (the 1105-sample encoder delay), yet the decoded samples align with the nominal times just as in `conversion.mkv`.
